# V5.19.0 — Client Acquisition & Enquiry Attribution

## Implemented

- Added privacy-conscious, session-only enquiry attribution: first landing page, last page before enquiry, referring domain/path and UTM campaign tags.
- Attribution is sent to the editorial inbox only when a visitor submits the enquiry form; it is not a pageview analytics stream and does not run a cross-site profile.
- Added the captured context to the internal enquiry email so the operator can compare discovery routes with qualified enquiries and paid outcomes.
- Updated the author-reported source question to ask where the author first heard about Second Pair, and added Discord and AI assistant / AI search as options.
- Made the homepage sample CTA clearer about what the sample demonstrates, its evidence limits and the lack of any obligation to book.
- Updated the privacy page to explain the limited attribution fields and their purpose.
- Fixed the “send another request” interaction so it resets the request type to sample.

## Why

The existing website already has problem-led discovery, service routing, proof-of-method content, pricing, and a detailed enquiry form. The most useful implementation from the client-acquisition plan was to connect enquiries to the route that produced them and make the sample's role clearer, rather than adding more pages without evidence.

## Attribution fields

- First landing page (path + UTM tags only)
- Last page viewed before enquiry (path only)
- Referrer (origin + path; query string excluded)
- UTM source, medium, campaign, content and term
- Author-reported first discovery source

Attribution is best-effort. Browser storage may be unavailable, and the form remains usable without it.

## Important limitations

- This does not automatically measure whether an enquiry becomes qualified, quoted, paid, repeated or referred. Record those stages in the lead pipeline template and compare them with the source/context in each enquiry email.
- No third-party analytics service was added.
- A successful production build and browser-based QA still need to be run in the normal project environment after dependencies are installed.
