# V5.19.1 — Service-page calculator defaults

## Issue
The shared pricing calculator always initialized to Alpha Reading with a 50,000-word manuscript, including when embedded on a different service detail page. This could make the estimate appear inconsistent with the service page the author was reading.

## Change
- Added an optional `initialService` prop to `PricingCalculator`; the pricing overview retains Alpha Reading as its default.
- Each service detail page now initializes the calculator to that page's service. The existing 50,000-word default remains consistent across calculators and can be changed by the visitor.
- Rates and minimum fees remain sourced from `config/services.ts`; no pricing values or pricing architecture were changed.

## Verification
- Confirmed all nine service slugs exist in the central service configuration.
- Confirmed the service detail page passes `s.slug` to the calculator and the pricing overview does not override its Alpha Reading default.
- Confirmed the calculator reads the selected service's rate and minimum from the central service configuration.
- Full production build and browser rendering were not run in this environment; this is a targeted source-level fix, not a claim of live-site verification.
