# V5.20.1 — Consent implementation audit and remediation

## Audit result
The first V5.20.0 source review found that the banner gated initial Google Analytics loading, but consent mode was not explicitly initialized to denied, and the site's existing `VisitContext` continued to write first-party attribution values to `sessionStorage` before consent. That attribution storage was outside the new banner's stated optional-analytics choice.

## Remediations applied
- Added explicit Google Consent Mode defaults before Google tag configuration, granting analytics storage only after an affirmative choice and keeping advertising consent denied.
- Gated first-party enquiry-attribution session storage on the same opt-in choice.
- Removed stored attribution keys when a visitor rejects or withdraws analytics consent.
- Fixed re-acceptance after withdrawal so an already-loaded tag receives an explicit consent-granted update again.
- Added Escape-key dismissal for the preferences dialog.
- Updated README wording to include first-party attribution in the optional analytics choice.

## Static checks performed
- The Google tag loader is referenced only from `components/ConsentManager.tsx`, not the root layout.
- The consent manager uses the expected measurement ID `G-RB9DS44MBZ`.
- The banner has accept, reject, and settings actions.
- Attribution storage checks the consent key before writing; denial removes previously stored attribution keys.
- The footer exposes a persistent Cookie settings link, delegated by the client consent manager.
- Privacy policy documents the analytics choice and the way it can be changed.

## Remaining verification / limitations
- A production Next.js build and browser-based interaction test were not completed because dependencies could not be installed in the audit environment (the package install timed out; the archive has no `node_modules`).
- Live Google Analytics Realtime and network-request verification must be completed after deployment.
- This is a custom lightweight consent manager, not a certified CMP. Applicable regional legal requirements and the site's privacy notice should be reviewed before launch.
- The preference dialog supports Escape dismissal but does not yet implement a complete focus trap/focus restoration pattern. This is an accessibility improvement recommended before treating the dialog as fully audited.
