# V5.20.3 — Phase 1 private onboarding

## Delivered

Added a private noindex onboarding route at `/onboarding/feedback-to-final-manuscript`. The route is gated by the server-side `ONBOARDING_ACCESS_TOKEN` and remains absent from public navigation.

Added a seven-step client form covering project details, intended reader effect, current uncertainty, reader evidence, manuscript context, editing expectations, and consent/submission. Conditional fields appear for existing feedback, revisions, series context and real deadlines.

Added support for the current manuscript plus optional feedback, previous-version and supporting-document uploads in DOCX or PDF format. The server validates the access token, required fields, email format, allowed file types, file signatures, per-file size and combined upload size.

Added `/api/feedback-to-final-onboarding`, which creates a structured internal calibration brief email with attachments through the existing Resend configuration and sends a confirmation email to the author.

Added `config/onboarding.ts`, `docs/internal-calibration-brief.md`, and the private onboarding route entry in `public/manus-routes.json`. Added the required `ONBOARDING_ACCESS_TOKEN` entry to `.env.example`.

## Phase 1 operating limitation

Payment confirmation, token generation, project records and staff authentication remain manual. The team must set a long random `ONBOARDING_ACCESS_TOKEN` in the production environment and issue the onboarding URL manually only after the 20% deposit is confirmed. This single-token approach is suitable for a small initial pilot, not for scaled multi-project operations.

## Validation

The production build completed successfully with 74 routes generated. Runtime checks confirmed that the onboarding page denies a missing or invalid token, renders with the valid token, includes noindex metadata, serves the route manifest, and the API rejects an invalid token with HTTP 403.
