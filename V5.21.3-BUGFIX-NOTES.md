# v5.21.3 bug-fix pass

Found by building the site and testing every page, form and API route in a browser and with direct requests.

## Fixed
- **Homepage colour contrast regression:** the gold stage numbers in the new homepage package panel (`.homepage-package-stages b`) were 3.99:1 on the dark panel (AA needs 4.5:1). Now `#c4a26a` (5.1:1). Verified on all 61 pages, mobile and desktop.
- **Onboarding API returned a generic 500 when the email service could not be reached.** Delivery failures now return a clear 502 and are logged. A failed *confirmation* email no longer turns an already-delivered intake into an error (which invited duplicate submissions).
- **DOCX/PDF uploads were rejected when the browser reported an empty or generic file type** (common on some Windows/Android setups). The onboarding and sample-request routes now accept those when the extension and the file signature are both valid. Fake files are still rejected.
- **Onboarding form lost its file on Back:** going back to step 1 showed an empty file picker and forced a re-select. The form now keeps the file and shows "Selected: filename". The "Please upload the current manuscript" message now displays (it was set but gated behind a status that never matched).
- **Access token handling:** token comparison is now constant-time (`config/token.ts`), and the private onboarding page sends `Referrer-Policy: no-referrer` so the token in the URL cannot leak through a Referer header.

## Verified unchanged
Sitemap (60 URLs), robots.txt, canonicals, share images, favicons, 404/error pages, production-build env safeguards, noindex on terms/privacy/onboarding, Google verification tag.

## You must set on the host
`ONBOARDING_ACCESS_TOKEN` (long random value). Without it the onboarding page shows "This onboarding link is not available."
