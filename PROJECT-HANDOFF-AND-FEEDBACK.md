# Project Handoff and Feedback

## Handoff record

Every confirmed project should have one internal record containing:

- Client
- Email
- Manuscript title
- Genre
- Word count
- Service
- Price
- Deliverables
- Exclusions
- Start date
- Delivery date
- Author's original concern
- Key findings from sample/inquiry
- Previous feedback supplied
- Special instructions
- File/version being edited

## Before work starts

Confirm that the file being worked on is the agreed version. Record the filename and date received.

## Before delivery

Check:
- all agreed deliverables are present
- filenames are clear
- comments/reports are readable
- major findings are easy to find
- no promised item has been omitted
- the work does not silently exceed the agreed scope

## After delivery

Ask for useful feedback after the author has had enough time to review the work.

Record:
- what the author found useful
- what was unclear
- whether the original question was answered
- any service gap
- any follow-up work the author requested

Do not turn feedback into an automatic testimonial request.

## Learning loop

Client feedback should return to the knowledge system only as an anonymised pattern or process improvement. Do not copy private manuscript material into public marketing.
